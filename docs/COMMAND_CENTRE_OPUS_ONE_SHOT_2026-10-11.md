## Voice: “Hey Jarvis” using the LOCAL, OPTIONAL existing stack
- Audit nod/MAZ Core voice, STT, TTS and the installed Hermes gateway before adding anything. Do not create another voice agent. **First deliver push-to-talk.** If not wired, keep the command editor usable with keyboard and clearly say voice isn't connected.
- Evaluate [dscripka/openWakeWord](https://github.com/dscripka/openWakeWord): Windows supports ONNX Runtime. Run only locally with one microphone owner, 16kHz mono 16-bit PCM, input frames sized to the API, configurable score/cooldown, and local Silero VAD filtering. Start with existing supported `hey jarvis` model (where present); don't fabricate detection reliability. Wake word should open a transient mic/listening window and pass a captured **utterance** to the existing nod/MAZ Core STT or tested alternative, then route the transcript into a **scoped MAZos mission preview**. No model runs while quiet. Audio remains local before intentional STT routing.
- IMPORTANT LICENSE: openWakeWord library code is Apache-2.0, but included pretrained models are **CC BY-NC-SA 4.0**. Use only within licence scope for this personal tool; before reuse in any commercial Maz Works product, secure appropriate commercial model rights or replace with a properly licensed alternative. Record the chosen model and attribution.
- If an audio response helps, reuse already-installed TTS, otherwise Piper [OHF-Voice/piper1-gpl](https://github.com/OHF-Voice/piper1-gpl) is only a candidate after package/licence review. Do not assume cloud Fish Audio is free.
- Voice UX: 3 calm statuses **Off / Waiting for wake word / Listening** plus Processing/Failure only while relevant; a subtle thin-ring/pulse motif, one toggle and one mic action. No constantly moving hologram, no animated talking head, no auto-start on login unless explicitly enabled, no retention by default. Hardware/software mute, clearly visible mic ownership, release audio device and stop detector on exit. Headphones/speakers may trigger false positives: test real conditions. Pause when PC sleeps; recover after resume.
- Voice cannot authorise deployments, PR merges, purchases, account changes, outreach, sensitive information access or shift acceptance. Always require explicit existing approval UI/handoff.

## Interface rules
Warm off-white / charcoal / subdued accent, not RGB neon, glass-card soup or sci-fi cosplay. Use the project's existing `docs/MAZOS_DESIGN_DIRECTION.md` where consistent; change conservatively with justification and owner-readable screenshots. Responsive from phone 390px to desktop 1440px, keyboard accessible, reduced-motion friendly. A single quiet “MAZos” identity plus **one intelligent command surface**. No fake activity dots. Every row answers: **who / what / machine / model if known / state / evidence / when / next action**. Default to a focused list with right-hand detail panel; expand an agent to see subagents, task tree, PR/receipt and last error. Agents list grouped by machine/harness, not subscription brand. Current work on top. Need one clear next item to ship; user may pin up to three. Avoid excessive alert panels.
